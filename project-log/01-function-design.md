# 功能设计

## 模块概览

| 模块 | 说明 | 负责人 |
|------|------|--------|
| Profile 管理 | 管理环境列表、名称、目录、最近使用时间、磁盘占用和删除 | Codex |
| 浏览器引擎管理 | 检测、安装确认、启动和关闭官方 Stable Chrome；Chrome 缺失时可使用用户确认的 Edge 备用引擎 | Codex |
| CDP 指纹注入 | 通过 Chrome DevTools Protocol 注入轻量 navigator 差异 | Codex |
| 主窗口 | 环境列表、详情栏、操作按钮、错误展示、设置入口 | Codex |
| 环境备注 | 为每个环境保存一条轻量纯文本备注，辅助识别用途 | Codex |
| 外部链接 | 接收系统外部 http / https 链接，并转发到默认环境 | Codex |
| 系统托盘 | 快速启动 / 关闭环境、关闭全部、打开主窗口、退出 | Codex |
| 设置与更新 | Chrome 状态、数据目录、语言、更新检查、联系方式 | Codex |
| 本地化 | 保留 BrowserIsolator 的 7 语言界面 | Codex |
| 安装与发布 | Windows 安装包、安装路径、数据目录和卸载行为 | Codex |

## 模块一：Profile 管理

### 功能列表

- [ ] 默认创建 `p1`、`p2`、`p3` 三个环境。
- [ ] 新增环境，目录命名为下一个可用 `pN`。
- [ ] 重命名环境，自定义名称只影响展示，不改变目录名。
- [ ] 编辑环境备注，备注为可选纯文本，最多 120 个字符。
- [ ] 删除未运行环境，要求输入环境名称确认。
- [ ] 删除时将 profile 目录移入 Windows 回收站。
- [ ] 扫描每个环境的磁盘占用和最近使用时间。
- [ ] 保存和读取 `%LOCALAPPDATA%\ChromeIsolator\config.json`。

### 业务逻辑

```text
用户新增环境 → 生成 pN → 创建 Profiles\pN → 保存配置 → 刷新列表
用户重命名 → trim 输入 → 更新 displayName → 保存配置
用户编辑备注 → 小弹窗输入 → trim 并限制长度 → 更新 note → 保存配置
用户删除 → 检查未运行 → 输入名称确认 → 移入回收站 → 移除配置 → 刷新列表
```

### 边界情况

- 正在运行或关闭中的环境禁止删除。
- 配置文件不存在或损坏时使用默认配置。
- profile 目录缺失时启动前自动补建。
- 磁盘占用扫描失败时显示为空，不阻塞主流程。
- 用户自定义名称为空时展示默认名称，例如“环境1”。
- 备注为空时不在详情区域显示；左侧列表保持简洁，不展示备注。

## 模块二：浏览器引擎管理

### 功能列表

- [ ] 优先检测当前可用的官方 Stable Chrome 可执行文件。
- [ ] 未检测到 Chrome 时展示首次运行说明，不自动下载、不静默安装。
- [ ] 用户明确确认后下载并运行官方 Stable Chrome 安装包。
- [ ] Chrome 缺失时允许用户明确选择 Microsoft Edge Stable 作为备用 Chromium 引擎。
- [ ] 不使用 Chrome for Testing、Beta、Dev、Canary。
- [ ] 启动指定环境，传入独立 `--user-data-dir`。
- [ ] 启动参数始终包含 `--no-first-run` 和独立 `--user-data-dir`。
- [ ] 默认基础模式不启用调试端口；仅在差异模式开启时分配调试端口，首选端口为 `40000 + 环境编号`。
- [ ] 关闭单个环境、关闭全部环境、退出前关闭全部。
- [ ] 显示当前浏览器引擎来源、路径和版本。
- [ ] 提供重新检测 / 安装官方 Chrome 的入口。

### 业务逻辑

```text
应用启动 → 确保数据目录 → 加载配置 → 检测 Chrome → 首次运行窗口说明隔离策略 → 用户选择安装 Chrome / 使用 Edge 备用 / 稍后处理
启动环境 → 校验浏览器引擎 → 传入独立 user-data-dir 启动进程 → 若启用差异模式则分配端口并启动 CDP 注入 → 记录运行状态
关闭环境 → 若存在 CDP 连接则断开并请求浏览器关闭 → fallback 到窗口关闭 → 超时后强制结束 → 更新状态和最近使用时间
```

### 边界情况

- Chrome 不可用时进入首次运行 / 引擎设置视图，不做自动安装。
- Edge 备用只在 Chrome 缺失且用户明确选择后启用；Chrome 一旦可用仍优先使用 Chrome。
- 端口被占用时向后尝试有限范围，失败后在环境详情中展示错误。
- profile 被 Chrome 锁定时启动失败并显示错误，可重试或清除错误。
- 应用退出时如果仍有运行环境，提示用户确认；确认后关闭全部再退出。
- 严禁读取或修改 `%LOCALAPPDATA%\Google\Chrome\User Data`，避免影响用户原本 Chrome 的插件、设置、登录用户和启动状态。

## 模块三：CDP 指纹注入

### 功能列表

- [ ] 根据环境编号稳定生成 CPU 核心数和内存值。
- [ ] 轮询 `http://127.0.0.1:{port}/json/version` 等待 CDP 就绪。
- [ ] 连接 browser-level WebSocket。
- [ ] 启用 `Target.setDiscoverTargets` 和 `Target.setAutoAttach`。
- [ ] 对已有 page target 和新打开的 page target 注入脚本。
- [ ] 断线后有限重连。
- [ ] 关闭环境时断开 WebSocket 并清理状态。

### 业务逻辑

```text
Chrome 启动成功 → 等待 CDP → 连接 browser WebSocket → 自动 attach page target → 注入脚本 → 监听新 target
```

注入脚本只覆盖：

```javascript
Object.defineProperty(navigator, 'hardwareConcurrency', { get: () => value, configurable: true });
Object.defineProperty(navigator, 'deviceMemory', { get: () => value, configurable: true });
```

### 边界情况

- CDP 未就绪时指数退避轮询。
- 某个 target 注入失败时记录日志，不关闭整个环境。
- WebSocket 断开时有限重连，超过次数后停止。
- 该模块只做轻量差异，不扩展为完整设备模拟。

## 模块四：主窗口

### 功能列表

- [ ] 左侧环境列表：名称、运行状态、最近使用、磁盘占用、错误标记。
- [ ] 运行中和关闭中的环境排在前面。
- [ ] 未运行环境按最近使用时间排序。
- [ ] 右侧详情栏：基础信息、路径、调试端口、错误、操作、高级信息。
- [ ] 右侧详情栏在备注非空时展示备注。
- [ ] 双击环境行启动。
- [ ] 行按钮启动 / 关闭。
- [ ] 工具栏：添加环境、设置、全部关闭。
- [ ] 重命名弹窗。
- [ ] 编辑备注弹窗。
- [ ] 删除确认弹窗。

### 业务逻辑

```text
选择环境 → 详情栏显示当前状态和操作
点击启动 → Chrome 管理启动环境 → UI 状态变为启动中 / 运行中
点击关闭 → Chrome 管理关闭环境 → UI 状态变为关闭中 / 未启动
```

### 边界情况

- 没有环境时展示空状态。
- 没有选中环境时详情栏展示提示。
- 启动中 / 关闭中禁用重复操作。
- 错误可清除，清除不改变实际 profile 数据。
- 备注为空时不占用详情布局；备注编辑不影响浏览器启动状态。

## 模块五：外部链接

### 功能列表

- [ ] 设置页提供“外部链接”配置项。
- [ ] “打开到”下拉选择外部链接默认进入的环境。
- [ ] 未显式选择时默认使用编号最小的 `pN` 环境。
- [ ] “设为默认浏览器”按钮发起当前用户级浏览器注册，并打开 Windows 默认应用设置。
- [ ] 应用启动参数和单实例管道只接收 `http` / `https` URL。
- [ ] 目标环境未运行时启动环境并打开链接。
- [ ] 目标环境启动中时将链接放入内存队列，启动完成后依次打开。
- [ ] 目标环境已运行时再次启动 Chrome 并传入同一 `--user-data-dir` 和 URL，让 Chrome 交给已有 profile 处理。
- [ ] 浏览器引擎未就绪或没有环境时弹出小提示，并提供复制链接按钮。

### 业务逻辑

```text
系统打开链接 → ChromeIsolator.exe 接收 URL → 若已有实例则通过管道转发
→ 选择配置环境或最小 pN → 校验浏览器引擎
→ 未运行则启动并带 URL / 启动中则排队 / 已运行则追加 URL
```

### 边界情况

- 非 `http` / `https` 链接不处理，并提示复制链接。
- 没有环境时不静默吞掉链接，提示用户先创建环境。
- 浏览器引擎未准备好时不缓存复杂重试，只提示原因并允许复制链接。
- 正常外部链接处理不主动唤起主窗口；只有错误提示需要小弹窗反馈。

## 模块六：系统托盘

### 功能列表

- [ ] 主窗口关闭时隐藏到托盘，不退出应用。
- [ ] 托盘菜单列出运行中的环境，可关闭。
- [ ] 托盘菜单列出未运行环境，可启动。
- [ ] 支持全部关闭。
- [ ] 支持全部关闭并退出。
- [ ] 支持打开主窗口。
- [ ] 支持检查更新。
- [ ] 退出时如果有环境运行，需要确认。

### 业务逻辑

```text
用户点击窗口 X → 隐藏主窗口 → 托盘继续驻留
用户选择退出 → 若有运行环境则确认 → 关闭全部 Chrome → 退出应用
```

### 边界情况

- 托盘菜单打开时需要使用最新环境状态。
- 主窗口已隐藏时“打开主窗口”需要激活并置前。
- 退出过程中避免重复触发关闭逻辑。

## 模块七：设置与更新

### 功能列表

- [ ] 显示当前浏览器引擎状态、路径和版本。
- [ ] 打开当前浏览器引擎文件夹。
- [ ] 重新检测 / 安装官方 Chrome。
- [ ] 显示数据目录。
- [ ] 打开数据目录和 Profiles 目录。
- [ ] 复制数据目录路径。
- [ ] 切换语言。
- [ ] 切换高级详情显示。
- [ ] 设置外部链接默认目标环境。
- [ ] 发起设为系统默认浏览器请求。
- [ ] 显示应用版本。
- [ ] 检查 GitHub Release 更新。
- [ ] 打开 Releases 页面和 Issues 页面。
- [ ] 复制联系邮箱。

### 业务逻辑

```text
用户打开设置 → 读取当前状态 → 执行文件夹 / 复制 / 更新检查操作 → 弹窗反馈结果
```

### 边界情况

- 有环境运行时避免切换浏览器引擎或重新安装 Chrome。
- 更新检查失败时显示网络错误，不影响本地功能。
- 多语言切换即时影响界面文本。
- 没有环境时外部链接目标为空；真正收到外部链接时提示用户先创建环境。

## 模块八：本地化

### 功能列表

- [ ] 中文。
- [ ] English。
- [ ] 日本語。
- [ ] 한국어。
- [ ] Deutsch。
- [ ] Français。
- [ ] Русский。

### 业务逻辑

```text
首次启动 → 读取系统语言 → 匹配支持语言 → 无匹配则默认中文
用户切换语言 → 保存偏好 → UI 立即刷新
```

### 边界情况

- 翻译缺失时回退英文，再回退 key。
- Windows 特有文案需要单独本地化，例如“回收站”“系统托盘”“安装包”。
