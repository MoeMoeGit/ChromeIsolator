# 决策与经验

仅保留仍约束当前项目的重要取舍和防复发信息。记录按新到旧排列。

## D-010：跨平台的新建与恢复语义

- 状态与日期：用户确认，2026-09-26。
- 新建环境（含首次生成）默认开启采集、关闭差异；旧配置缺字段及磁盘恢复维持关闭，不迁移已有设置。
- 有效配置的目录缺失时保留名称、备注及模式并补建空目录，不丢弃配置；这不恢复已丢失的浏览器数据。
- 继续保留 Windows 系统 Chrome/Edge、托盘、MSI 和更新下载流程等平台差异。

## D-009：采集模式与差异模式相互独立

- 状态与日期：当前有效；2026-07-07。
- 选择：采集模式只开放 `41000 + N` 起始的本机 CDP 端口，供本机工具连接；差异模式才注入两个 navigator 属性。两者可同时启用并共用采集端口。
- 依据：采集已登录页面不应改变浏览器环境特征；基础模式兼容性优先。
- 边界：CDP 无认证，必须绑定 `127.0.0.1`；运行中环境不可切换模式。
- 重评条件：采集工具改用非 CDP 通信，或 Chrome 的回环调试安全模型变化。

## D-008：大量环境的模式设置使用二级管理窗口

- 状态与日期：当前有效；2026-05-25，2026-07-08 调整布局。
- 选择：设置页只展示概览，具体环境开关进入可搜索的二级窗口；采集是主路径，差异是低频并列开关，并提供采集批量操作。
- 依据：环境列表可能很长，直接铺在设置页会撑爆布局，多语言长文案也会挤压环境名。
- 防复发：不要把完整环境复选列表重新塞回设置主页。

## D-007：MSI 使用最小反馈流程，升级不强杀应用

- 状态与日期：当前有效；2026-05-23，2026-07-08 完善。
- 选择：欢迎、进度、完成三页；固定安装目录；完成页默认启动；运行中提示从托盘退出后重试；卸载保留用户数据。
- 依据：普通用户无需选择安装目录或阅读重复许可页，强杀会绕过受管浏览器清理。
- 边界：早期包允许未签名，SmartScreen 指引必须保留；签名在正式分发需要更高信任度时重评。

## D-006：主界面环境卡片必须由布局拉伸

- 状态与日期：当前有效；2026-05-23。
- 选择：列表容器使用能正确填充的 Grid/拉伸关系，不用硬编码 `MinWidth` 修补卡片宽度。
- 依据：历史上 `DockPanel` 中 ListBox 非最后填充子元素导致右侧截断和留白；硬编码在不同窗口宽度和 DPI 下反复失效。
- 防复发：改列表模板后在可调左栏和多 DPI 下实际检查。

## D-005：关闭主窗口驻留托盘

- 状态与日期：当前有效；2026-05-21。
- 选择：窗口关闭等于隐藏；托盘是 Windows 上的常驻入口，真正退出需关闭所有受管环境。
- 依据：等价承接 macOS 菜单栏的快速启停体验，同时符合 Windows 使用习惯。
- 防复发：区分“隐藏”“全部关闭浏览器”“退出应用”，不要增加语义重复入口。

## D-004：轻量环境差异不是反检测能力

- 状态与日期：当前有效；2026-05-21，2026-05-25 改为按环境可选。
- 选择：仅覆盖 `navigator.hardwareConcurrency` 和 `navigator.deviceMemory`；默认基础模式不注入。
- 依据：产品目标是本地隔离而非设备伪装，更多覆盖会增加兼容、维护和合规风险。
- 重评条件：仅在产品边界被明确改变并完成安全、兼容和用户承诺评估后讨论。

## D-003：共享官方浏览器程序，绝不共享默认 profile

- 状态与日期：当前有效；2026-05-22。
- 选择：优先复用官方 Stable Chrome 的程序文件；每次启动强制使用 ChromeIsolator 的独立 `--user-data-dir`。Chrome 缺失时用户确认安装，Edge 仅是明确选择的备用。
- 依据：官方 Stable 的安装与更新更可靠；真正需要隔离的是用户数据目录。禁止 Testing、Beta、Dev、Canary 和第三方便携版。
- 防复发：任何启动路径，包括外部链接，都必须检查独立 profile 参数；不得读取默认 Chrome/Edge 用户目录。

## D-002：配置使用 JSON，环境数据由浏览器管理

- 状态与日期：当前有效；2026-05-21。
- 选择：小规模应用配置放 `config.json`，写入时保留 `.bak`；Chrome profile 保持原生目录，不引入数据库。
- 依据：数据规模小、易备份和排查，浏览器数据不适合由应用重建模型。
- 重评条件：出现复杂审计、搜索或并发写入需求时评估 SQLite。

## D-001：采用 C# / WPF / .NET 8 和 WiX MSI

- 状态与日期：当前有效；2026-05-21。
- 选择：Windows 原生桌面栈，轻量 MVVM 分层；发布 self-contained win-x64 ZIP 和 WiX MSI。
- 依据：项目只面向 Windows 10/11 x64，需要托盘、注册表、回收站、进程和安装器的原生集成。
- 重评条件：产品明确扩展到跨平台，且迁移收益大于现有原生集成成本。
